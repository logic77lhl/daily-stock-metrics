# 每周自动指标

每日自动获取 **A股市值前100** 的公司，并计算：

- 日线 / 周线 / 月线 **KDJ 的 J 值**
- **MA20 / MA60 双均线状态**（多头/空头排列）、价距MA20%、量比
- 当前 **PE_TTM、PB_MRQ** 及其 **历史分位%**（全历史 + 近5年窗口）
- 所属**行业**（A股）

结果按日期输出到 `output\<日期>\` 目录。

## 运维须知

几个每天都会用到、但踩过坑才写下来的规则：

- **「目标交易日」而不是「今天」**：`trading_calendar.py` 是**唯一**判断入口
  （workflow、三个 runner、heartbeat 都调它）。它同时回答两个不同的问题：

  | 问题 | 函数 | 用途 |
  | --- | --- | --- |
  | 现在该采集哪一天？ | `collection_target()` | 决定三个 runner 跑不跑、跑哪一天 |
  | 哪一天必须已经有数据？ | `latest_closed_trading_day()` | 决定 workflow 判红还是判绿 |

  两者在盘中是**不同**的，把它们混为一谈正是 2026-09 丢掉 8 个交易日的原因：
  当时用「今天 + `hour < 15`」判断，而 GitHub 的 schedule **实测延迟 4~8 小时**
  （北京的 16:30 触发点常在次日 00:00~02:00 才落地）。跨过午夜后「今天」变成了
  第二天、小时数是 0，于是判「未到收盘」直接跳过，gate 又把这次跳过当成
  「非交易日」放行 —— **整天数据静默丢失，而 Actions 全绿**。

  现在改为「最近一个已收盘、且其收盘价仍是数据源最新一根 K 线的交易日」：

  | 时刻 | 目标日 | 采集 |
  | --- | --- | --- |
  | 当天 23:46 | 当天 | ✅ |
  | 次日 01:00 / 08:00 | **仍是前一天** | ✅（跨午夜不再是歧义，反而成了补跑窗口） |
  | 次日 10:00 | 前一天 | ❌ 拒绝：最新一根 K 线已是当日实时 bar |
  | 周六/节假日 | 节前最后一个交易日 | ✅ |

  最后一行是 gate 自动绿灯的原因：节假日时「必须有的那天」= 节前最后一个交易日，
  它的 DONE 早就存在。而「因为故障没跑」会实打实地判红。
  年度表需每年按上交所/深交所休市公告更新（`A_SHARE_HOLIDAYS` /
  `HK_EXTRA_HOLIDAYS`，港股通为两者并集）；未覆盖年份 fail-open 放行 + 告警。
  本地验证：`DSM_CALENDAR_NOW=2026-10-09T01:00 python trading_calendar.py plan`。
- **每一行都记录自己的数据日期**：`metrics_*.csv` 的 `数据日期` 列写的是这一行
  实际取自哪一根 K 线，质量门会拿它和目标交易日比对。这是 2026-10-02 那次事故的
  补丁 —— 国庆休市，但旧版 workflow 不知道，把 09-30 的收盘价当成 10-02 发布了出去
  并写了 DONE。只校验行数/填充率是抓不住「数据完好、只是日期错了」的。
- **东财会按 IP 整批拒绝**：`push2*.eastmoney.com`（列表/排行接口）对云厂商出口 IP
  会直接 RST —— 实测 4 个主机、12 次重试全部 `RemoteDisconnected`，而同一时刻
  `datacenter-web`（估值）、腾讯 K 线、`quote.eastmoney.com` 都正常。这是
  **主机级、非瞬时**的封锁，指数退避对它没有任何价值。所以：
  - `http_util.HostPool` 让连续失败的主机**退役**，把最坏耗时从 351 秒压到约 45 秒；
    快速失败是为了把机会让给**不同时刻**的重试（workflow 的 Retry 步骤 + 下一个 cron），
    在进程内死等只是烧预算。
  - 三个「取列表」的步骤都有**降级路径**：接口不可用时改用观察池历史名单
    （`stock_pool.list_from_pool`）。成分日间变化极小，而**指标仍然全部实抓**，
    所以降级只影响「今天谁算 Top100」，不影响任何一行指标。DONE 里会记
    `universe=pool-fallback`。
  - 三个取列表的调用点原来传的是 `requests` **模块**而不是 `Session`，
    而 `requests.get()` 内部会 `with Session()` —— 每次重试都新建连接、重做 TLS
    握手，连接池完全失效。现在 `get_json` 会直接拒绝模块，堵死这个坑。
- **必须限流，否则腾讯也会封你**：`fetch_metrics` 是 8 线程 × 每标的 3 个周期
  ≈ 340 次请求，原来只有**每线程** `sleep(0.15)`，合起来约 50 次/秒 —— 实测直接
  把腾讯打到限流（响应变非 JSON），随后**113 只标的全灭**。这不是回填脚本的
  问题：线上每天的日常更新走的是同一条路径。现在 `http_util.RateLimiter` 提供
  **跨线程**的全局最小间隔，默认 0.30 秒（≈3.3 次/秒），可用
  `DSM_REQUEST_INTERVAL` 调整；`fetch_kline` 也补上了真正的退避重试
  （原来是 `retries=1` + 不 sleep 的双 host 循环，等于没有重试）。
  另外全军覆没时会抛自解释的错误，而不是让下游在「CSV 不存在」上崩掉。
- **站点缺数据必须看得见**：`build_pages.py` 会比对「最近一个已收盘交易日」，
  缺哪个市场就在首页挂一条红色「数据已过期」横幅。站点也**总是**部署 ——
  旧版要求三个市场全部完成才发布，结果是「A股天天成功、ETF/港股被拦」时
  站点整整三周停在 2026-09-18：有数据却不给看，比缺一块更糟。
- **历史回填**：`backfill.py` 用历史 K 线 + 历史估值序列重算缺失交易日。
  指标公式只依赖「截至当日的序列」（`kdj_j`/`ma_values`/`volume_ratio` 都取
  `iloc[-1]`，`percentile` 取 `(series <= value).mean()`），所以把序列切到
  `date <= D` 得到的**就是 D 日收盘后的口径**，不是近似。
  A 股还会用估值接口的历史 `TOTAL_MARKET_CAP` 重建**当日真实的市值前 100**。
  港股/ETF 没有历史估值与市值，PE/PB 留空、排名沿用观察池顺序（与它们正常
  运行时的口径一致）。回填出来的 DONE 带 `backfilled=true`，不冒充实抓。

  ```powershell
  python backfill.py --all --from 2026-09-21 --to 2026-10-08 --dry-run
  python backfill.py --all --from 2026-09-21 --to 2026-10-08
  ```
- **产物保留 30 个交易日**：`prune_outputs.py` 只保留最近 `DSM_KEEP_DAYS`（默认 30）
  个交易日的目录与带日期的文件；裁剪用 `git rm`（同时删索引与工作区）。
  `output/stock_charts.html`（3.2 MB、每日重建、站点不引用）已不再入库。
- **等待预算**：各步骤通过 `DSM_DEADLINE_SEC` 限制最长等待，超出即抛
  `DeadlineExceeded` → 不写 DONE → 由 workflow 的重试步骤补跑，
  而不是在里面死等到 job 超时。
- **heartbeat 的 PAT 权限**：`HEARTBEAT_TOKEN` 需要
  `Contents: Read` + `Actions: Read and write`。权限不足时探测/补触发会
  显式报错退出（早期版本会把 403 当成「缺失」，导致兜底机制静默失效）。
  heartbeat 同样按「目标交易日」判断 —— 旧版用 `check --min-hour 15`，
  跨午夜后返回「未到收盘」就 `exit 0`，**恰好在最需要它的时段完全失效**。
- **失败诊断要留痕**：workflow 会把 `run_*.log` 与 `failed_*.csv` 作为 artifact
  上传（保留 14 天）。fetch 层的重试明细以前只进 stdout，仓库里的 `run_*.log`
  只有三行，事后完全无法判断「重试了几次、哪个主机失败」。
- **workflow YAML 结构守卫**：`tests/test_workflows.py` 会检查 `run: |` 块有没有
  被顶格内容截断（内联多行 Python 最容易踩）。这不是洁癖：块被截断会让**整份
  workflow 非法**，GitHub 以「workflow file issue」在 0 秒失败且日志为空 ——
  此后所有定时采集静默停摆。守卫带自证测试（喂一份坏写法，必须被抓到）。
- **候选池与页面体积**：首页体积约为 `1.1 KB × 候选池上限`，调大
  `max_candidates` 时请一并留意仓库体积。

## 回测

```powershell
python backtest.py                       # 全市场
python backtest.py --market 个股 --horizons 1,5 --cost 0.15
python backtest.py --strategy "自定义=日线J<20 and MA20>MA60"
python backtest.py --bars 800            # 每只标的多长价格序列（影响缓存键）
```

- 内置策略含：双均线多/空头、价上MA20且多头排列、KDJ三周期共振/分化、超卖+多头排列、低位放量等组合
- 价格统一采用**最新前复权序列**重建（跨日可比），缓存在 `backtest_results/kline_cache/`

### 成交价口径（2026-10 修正前视偏差）

原来的成交价是**信号日收盘价**，而所有信号（`日线J`/`MA20`/`MA60`/`量比`/`PE历史分位%`）
都由**同一根收盘价**算出 —— 「收盘后才知道信号，却按收盘价成交」，是前视偏差。
现在改为：

```
T 日收盘后出信号  →  T+1 开盘价建仓  →  持有 h 个交易日后收盘平仓
```

实测影响（同一批 44523 个策略×交易样本，逐笔配对，0 未匹配）：**胜率下降 0.5~4pp**，
平均收益下降 0.03~0.16pp。KDJ 均值回复类策略受影响最大
（`三周期共振偏弱` h=3 从 +0.13% 翻负到 +0.04%；`超卖+多头排列` h=1 胜率 44.0%→39.6%）。
被去掉的隔夜跳空在这个样本里值约 +0.10pp/笔。

### 已知偏差（报告页脚「方法与局限」里逐条披露）

- **幸存者偏差**：面板来自每日「市值前 100 + 观察池」，而观察池 365 天不出现即剔除，
  退市/长期下跌的标的被系统性移除；从未进入过 Top100 的标的也完全不在样本内。
- **成本口径**：`(卖出×(1-c)) / (买入×(1+c)) - 1`，`c` 默认 0.15% 单边。
  对 A 股大盘股勉强够，**对港股通偏低**（还有印花税/交易征费/结算费）。
- **重叠持有期**：h>1 时「不重叠累计净值」按 h 日切桶复利（h=1 与旧的日频复利一致）；
  旧实现把重叠持仓重复计入，会明显高估净值。
- **样本窗口**：交易必须在面板覆盖的最后一个**真实交易日**内完成，
  否则计入 `skip_horizon_beyond_panel`。这让数字可以从已提交的产物复现。
- 每个被剔除的样本都有计数器（`drop_no_price_series` / `drop_no_entry_bar` /
  `drop_no_exit_bar` / `drop_bad_price` 等），会打印并在报告里列表，不再静默丢弃。

- 价格序列的新鲜度门槛是「必须覆盖面板要求的最后一个交易日」（原来只是「5 个自然日内」，
  隔几天再跑就会拿旧价配新指标）；缓存键含 `bars`，且拒绝只存 close 的旧格式缓存。
- 收益已按 `--cost` 单边成本扣减（默认0.15%，覆盖佣金+税费+滑点），
  页面上的买入价/卖出价保留 3 位小数且收益由这两个价复算，**可手工验算**。

## 个股走势图

`output\stock_charts.html` 汇总全部历史日期的指标，为每只股票生成一张图
（**只在本地生成，不再提交进仓库** —— 单文件 3.2 MB 且每日重建）：

- **y 轴**：每日最新价（股价走势线）
- **x 轴**：日期
- **x 轴下方色带**：每天当日的周期信号（三周期共振超买/超卖、偏强/偏弱、新低、分化等）
- 鼠标悬停在曲线点或色块上，可查看该日股价、日/周/月 J 值、涨跌幅、PE/PB 及信号
- 顶部搜索框可按代码/名称筛选个股

仅当 candidates 数据含 `最新价` 时（2026-07-23 起）才有股价点；更早的日期仅显示信号色带。

## 开机自动运行

```powershell
powershell -ExecutionPolicy Bypass -File .\setup_autostart.ps1
```

- 若有管理员权限：注册为**计划任务**（登录时运行 + 每天19:00补跑）。
- 否则自动回退为**启动文件夹快捷方式**（下次登录时运行，静默）。

自动运行（非手动）时，若开始时间**早于 17:00**（收盘数据未更新），任务会直接跳过；请勿在收盘前运行。

取消：

```powershell
powershell -ExecutionPolicy Bypass -File .\remove_autostart.ps1
```

## 云端定时运行（GitHub Actions）

项目已托管到 GitHub，由 `.github/workflows/daily.yml` 定时执行，无需开机：

- **时间**：工作日北京时间约 17:30（GitHub 定时任务可能有几分钟到半小时延迟）
- **流程**：A股 → ETF → 港股 → **买入参考邮件** → 自动把 `output*` 结果提交回仓库（历史走势图持续累积）
- **邮件**：3 封市场报告（含"📌 今日速览"动态策略摘要，按近20日次日胜率自动选优）
  + 1 封跨市场「今日买入参考」（按胜率排序，最多10只，无命中不发）
- **GitHub 预览**：根目录 `摘要-A股.md` / `摘要-ETF.md` / `摘要-港股.md` / `摘要-买入参考.md` 每日自动更新；
  各日期目录下有完整 Markdown 版报告 `report_日期.md`
- **手机适配**：报告 HTML 已针对移动端优化（窄屏字体/布局自适应）
- **手动触发**：仓库页 Actions → daily-metrics → Run workflow
- **日志查看**：Actions 运行记录里可看每步输出
- **邮件配置**：通过仓库 Secrets（`SENDER_EMAIL` / `SENDER_AUTH_CODE` / `RECIPIENT_EMAIL`）注入，
  本地运行则读取同名用户环境变量

本地与云端互为备份：本机自启动若当天已跑完（DONE 标记在本地），云端仍会独立跑一遍并提交结果。

## 说明

- K线数据源：腾讯（`web.ifzq.gtimg.cn`）；估值/市值数据源：东方财富。
- 东方财富接口偶发限流，脚本已内置多主机切换 + 指数退避重试。
- 少数次新股上市时间短，部分周期 KDJ 或历史分位可能为空，属正常。
- 历史分位基于该股完整估值序列，值越低表示当前估值处于历史越低位。
- KDJ 参数：N=9, M1=3, M2=3；价格用前复权。
